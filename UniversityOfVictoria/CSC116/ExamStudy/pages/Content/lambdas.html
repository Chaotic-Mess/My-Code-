Lambdas

A compact reference to C++ lambdas: syntax, captures, and practical use with the STL.

Basics

A lambda is an inline function object with the form [capture](params) mutable -> ret { body }.

#include <iostream>
auto add = [](int a, int b) { return a + b; };
std::cout << add(2, 3) << '\n';

// Immediately-invoked lambda (IIFE)
[](const std::string& msg){ std::cout << msg << '\n'; }("Hello");

Captures

Capture external variables into the lambda's closure:

  • [=]: capture all used variables by value
  • [&]: capture all used variables by reference
  • [x] / [&x]: capture specific variables
  • Mix: [=, &x] or [&, x]
int x = 10;
auto byVal = [x]{ std::cout << x << '\n'; }; // copy
x = 20; byVal(); // prints 10

auto byRef = [&x]{ x++; };
byRef(); byRef();
std::cout << x << '\n'; // 22

Value vs Reference

  • By value: captures a snapshot at creation time. Inside the lambda, the captured copy is read-only unless the lambda is marked mutable.
  • By reference: the lambda refers to the original variable; mutations affect the original and observe subsequent changes.
  • Lifetime: avoid returning a lambda that references locals — it will dangle after the function returns.

Init-Capture & mutable

Init-capture computes or moves values into the closure: [y = expr]. Use mutable to modify captured-by-value variables inside the lambda.

int x = 10;
auto h = [y = x]() mutable { y++; std::cout << y << '\n'; };
h(); // 11
h(); // 12
std::cout << x << '\n'; // 10 (unchanged)

// Move-only example (C++14+)
auto p = std::make_unique<int>(5);
auto take = [q = std::move(p)]{ std::cout << *q << '\n'; };

Details

  • Init-capture: great for computing derived values once or moving ownership into the closure (e.g., unique_ptr).
  • mutable: allows changing the captured-by-value state for that lambda instance; it does not change the original variable.
  • Thread-safety: prefer init-capture over references when passing lambdas to async tasks to avoid shared-state races.

Generic Lambdas

Use auto parameters to write lambdas that work with multiple types.

auto maxOf = [](auto a, auto b) { return a < b ? b : a; };
std::cout << maxOf(1, 3) << '\n';
std::cout << maxOf(std::string("ab"), std::string("c")) << '\n';

// Trailing return for complex cases
auto sum = [](auto a, auto b) -> decltype(a + b) { return a + b; };

Details

  • Type deduction: parameters are deduced independently; use a trailing return when result type isn’t obvious.
  • Constraints: with C++20, add requires clauses to document valid argument types.

Algorithms

Lambdas make STL algorithms concise and expressive.

#include <algorithm>
#include <numeric>
#include <vector>
std::vector<int> v{1,2,3,4};
std::for_each(v.begin(), v.end(), [](int& n){ n *= 2; }); // 2,4,6,8
std::transform(v.begin(), v.end(), v.begin(), [](int n){ return n + 1; }); // 3,5,7,9
int s = std::accumulate(v.begin(), v.end(), 0, [](int acc, int n){ return acc + n; });

Tips

  • Prefer const& parameters when you don’t mutate elements.
  • Use captures to bring external thresholds/config into predicates.

Sorting

Provide custom comparators to std::sort to define ordering.

#include <algorithm>
#include <vector>
#include <string>
std::vector<int> a{5,1,3,4,2};
std::sort(a.begin(), a.end(), [](int x, int y){ return x > y; }); // desc

struct Person { std::string name; int age; };
std::vector<Person> p{{"Ann",20},{"Bob",18},{"Cara",22}};
std::sort(p.begin(), p.end(), [](const Person& lhs, const Person& rhs){ return lhs.age < rhs.age; });

Comparator rules

  • Must impose strict weak ordering: irreflexive, transitive, and consistent.
  • Comparators should not modify inputs or rely on external mutable state that changes during sort.

std::function

std::function type-erases callables (lambdas, function objects, functions). Great for callbacks.

#include <functional>
#include <vector>
std::function<int(int,int)> op = [](int a, int b){ return a + b; };

void apply(const std::vector<int>& v, std::function<void(int)> fn) {
    for (int n : v) fn(n);
}
apply({1,2,3}, [](int n){ std::cout << n << ' '; });

Details

  • Overhead: std::function has indirection and potential allocations; prefer templated callables for hot paths.
  • Flexibility: excellent for storing heterogenous callbacks and APIs.

Capturing this

Use [this] inside member functions to access members. Ensure the object outlives the lambda.

struct Counter {
    int count{0};
    void incBy(int step){
        auto doInc = [this, step]{ count += step; };
        doInc();
    }
};
Counter c; c.incBy(2); // c.count == 2

Safety

  • Prefer capturing specific members ([this] or structured captures) over global state.
  • Do not let async callbacks outlive the object; consider weak_ptr patterns.

Recursion

Enable recursion with std::function or by passing the lambda to itself.

#include <functional>
std::function<int(int)> fact = [&](int n){ return n <= 1 ? 1 : n * fact(n - 1); };

auto fib = [](auto& self, int n) -> int { return n<2 ? n : self(self,n-1) + self(self,n-2); };

Notes

  • std::function enables self-reference without naming a separate function object type.
  • Self-passing generic lambdas avoid std::function overhead and keep everything inline.

Pitfalls

  • Dangling references: never return a lambda that captures a local by reference.
  • Mutable confusion: without mutable, captured-by-value variables are read-only inside the lambda.
  • Expensive std::function: prefer templated callables when performance is critical.
  • Async + this: ensure objects outlive lambdas used in async callbacks.
  • Comparator rules: comparators must implement strict weak ordering.
