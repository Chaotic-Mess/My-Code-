Throwing and Catching Exceptions

Error handling in C++ using try-catch blocks, custom exceptions, and exception propagation.

What Are Exceptions?

Exceptions are a mechanism for handling runtime errors in C++. When an error occurs, we throw an exception. The program then searches for a matching catch block to handle it.

Key Concept: Exceptions allow you to separate error-handling code from normal program logic, making code cleaner and more maintainable.

Why Use Exceptions?

  • Handle errors that cannot be dealt with locally
  • Propagate errors up the call stack automatically
  • Separate error handling from normal code flow
  • Provide detailed error information
  • Clean up resources automatically (RAII)

Basic Try-Catch Syntax

The fundamental structure of exception handling uses try, throw, and catch:

#include <iostream>
#include <stdexcept>

int divide(int a, int b) {
    if (b == 0) {
        throw std::runtime_error{"Division by zero!"};
    }
    return a / b;
}

int main() {
    try {
        int result = divide(10, 0);
        std::cout << "Result: " << result << "\n";
    }
    catch (const std::runtime_error &e) {
        std::cout << "Error: " << e.what() << "\n";
    }
    return 0;
}
Error: Division by zero!

How It Works:

  1. try block: Contains code that might throw an exception
  2. throw statement: Creates and throws an exception object
  3. catch block: Handles the exception if the type matches

Throwing Different Types

You can throw any type in C++: integers, floats, strings, or objects.

#include <iostream>
#include <string>

int F(int x) {
    int bla{5};
    float haha{3.2};
    std::string foo{"hello"};
    
    if (x < 0) {
        throw bla;           // Throws int
    }
    if (x == 42) {
        throw haha;          // Throws float
    }
    if (x > 100) {
        throw foo;           // Throws string
    }
    return 6;
}

int main() {
    int y{1000};
    
    try {
        y = F(42);
    }
    catch (const int value) {
        std::cout << "caught (int) " << value << "\n";
    }
    catch (const std::string &value) {
        std::cout << "caught (string) " << value << "\n";
    }
    catch (...) {
        std::cout << "caught something else\n";
    }
    
    std::cout << "y = " << y << "\n";
    return 0;
}
caught something else y = 1000
Important: The catch block must match the exact type thrown. In this example, float is thrown but there's no catch (const float &) block, so it's caught by catch (...).

The Catch-All Handler

catch (...) catches any exception type. Use it as a last resort to prevent uncaught exceptions.

Standard Exception Classes

The C++ standard library provides several built-in exception classes in <stdexcept>: 

#include <stdexcept>

// Common standard exceptions:
std::runtime_error      // General runtime errors
std::logic_error        // Logic/programming errors
std::invalid_argument   // Invalid function arguments
std::out_of_range       // Out of range access (like vector.at())
std::domain_error       // Mathematical domain errors
std::length_error       // Length exceeds maximum

Example: Invalid Argument

#include <iostream>
#include <vector>
#include <stdexcept>

int last(const std::vector<int> &input) {
    if (input.size() <= 0) {
        throw std::invalid_argument{"Cannot get last element of empty vector!"};
    }
    return input.at(input.size() - 1);
}

int main() {
    std::vector<int> W{6, 10, 17};
    auto z{last(W)};
    std::cout << "z: " << z << "\n";
    return 0;
}
z: 17
Standard exceptions have a .what() method that returns the error message as a C-string.

Multiple Catch Blocks

You can have multiple catch blocks to handle different exception types. Catch blocks are checked in order from top to bottom.

#include <iostream>
#include <stdexcept>

void process(int value) {
    if (value < 0) {
        throw std::invalid_argument{"Negative value not allowed"};
    }
    if (value > 100) {
        throw std::out_of_range{"Value exceeds maximum"};
    }
    if (value == 42) {
        throw std::runtime_error{"The answer to everything is not allowed"};
    }
}

int main() {
    try {
        process(150);
    }
    catch (const std::invalid_argument &e) {
        std::cout << "Invalid: " << e.what() << "\n";
    }
    catch (const std::out_of_range &e) {
        std::cout << "Out of range: " << e.what() << "\n";
    }
    catch (const std::runtime_error &e) {
        std::cout << "Runtime: " << e.what() << "\n";
    }
    catch (...) {
        std::cout << "Unknown error\n";
    }
    return 0;
}
Out of range: Value exceeds maximum
Order Matters! Place more specific exception types before general ones. If you put catch (...) first, it will catch everything and subsequent catch blocks will never execute.

Custom Exception Classes

You can create your own exception types using structs or classes. This allows you to include custom data with your exceptions.

#include <iostream>
#include <vector>
#include <string>

struct InvalidGradeException {
    unsigned int grade_index{};  // Index of invalid grade
    int grade_value{};            // The invalid value
};

struct EmptyGradeArrayException {
    // Empty struct - just serves as a signal
};

float average_grades(const std::vector<int> &grades) {
    if (grades.size() <= 0) {
        throw EmptyGradeArrayException{};
    }
    
    float sum{0};
    for (unsigned int i{0}; i < grades.size(); i++) {
        const auto &g = grades.at(i);
        if (g < 0 || g > 100) {
            throw InvalidGradeException{i, g};
        }
        sum += g;
    }
    return sum / grades.size();
}

int main() {
    std::vector<int> grades1{90, 70, 80};
    std::vector<int> grades2{};                // Empty
    std::vector<int> grades3{90, 70, -80};    // Invalid
    
    const auto &G = grades3;
    
    try {
        auto av{average_grades(G)};
        std::cout << "Average: " << av << "\n";
    }
    catch (const EmptyGradeArrayException &e) {
        std::cout << "Error: Cannot average empty array\n";
    }
    catch (const InvalidGradeException &e) {
        std::cout << "Invalid grade at index " << e.grade_index
                  << ": " << e.grade_value 
                  << " not in [0,100]\n";
    }
    return 0;
}
Invalid grade at index 2: -80 not in [0,100]
Best Practice: Custom exceptions allow you to pass specific error information (like which index failed, what the invalid value was, etc.) to the exception handler.

Exception Propagation

When an exception is thrown, it "bubbles up" the call stack until a matching catch block is found.

#include <iostream>
#include <stdexcept>

int F(int x) {
    std::cout << "Inside F " << x << "\n";
    if (x > 10) {
        throw std::runtime_error{"Something bad happened"};
    }
    std::cout << "End of F, returning " << 10 * x << "\n";
    return x * 10;
}

int G(int y) {
    std::cout << "Inside G " << y << "\n";
    int result{0};
    try {
        while (y < 100) {
            result += F(y);  // F might throw
            y = 2 * y;
        }
    }
    catch (const std::runtime_error &e) {
        std::cout << "Caught in G\n";
        throw std::runtime_error{"Only partially handled!"};
    }
    std::cout << "End of G, returning " << result << "\n";
    return result;
}

int main() {
    int y{999};
    try {
        y = G(6);
    }
    catch (const std::runtime_error &e) {
        std::cout << "Caught in main\n";
    }
    std::cout << "y is " << y << "\n";
    return 0;
}
Inside G 6 Inside F 6 End of F, returning 60 Inside F 12 Caught in G Caught in main y is 999

What Happens:

  1. main() calls G(6)
  2. G(6) calls F(6) → succeeds, result = 60
  3. G(6) calls F(12) → throws exception
  4. Exception propagates to G's catch block
  5. G catches it, then throws a new exception
  6. New exception propagates to main
  7. main catches it and continues
Re-throwing: You can catch an exception, do some cleanup or logging, and then throw a new exception (or re-throw the same one with throw;).

Nested Try-Catch Blocks

You can have try-catch blocks inside other try-catch blocks. Inner exceptions are handled before outer ones.

#include <iostream>
#include <stdexcept>

int F(int start, int end) {
    int total{0};
    try {
        if (start < 1)
            throw std::runtime_error{"Start value too small"};
            
        for (int i{start}; i <= end; i++) {
            try {
                if (i > 5)
                    throw std::domain_error{"Too big"};
                total += i;
            }
            catch (std::domain_error &e) {
                std::cout << "F: Caught domain_error (inner)\n";
                throw std::domain_error{"Re-thrown from inner"};
            }
        }
    }
    catch (std::runtime_error &e) {
        std::cout << "F: Caught runtime_error (outer)\n";
        return 1000;
    }
    catch (std::domain_error &e) {
        std::cout << "F: Caught domain_error (outer)\n";
        return 42;
    }
    return total;
}

int main() {
    int sum{1000};
    try {
        sum = F(2, 4);
        std::cout << "sum = " << sum << "\n";
        sum = F(3, 6);  // This will throw
        std::cout << "sum = " << sum << "\n";
    }
    catch (...) {
        std::cout << "main: Caught something\n";
    }
    std::cout << "Final sum = " << sum << "\n";
    return 0;
}
sum = 9 F: Caught domain_error (inner) F: Caught domain_error (outer) sum = 42 Final sum = 42

Execution Flow:

  • Inner try-catch blocks are checked first
  • If inner catch doesn't handle it (or re-throws), outer catches are checked
  • Exception handling searches from innermost to outermost scope

What Happens When an Exception is Not Caught?

Uncaught Exceptions: If an exception is thrown and not caught anywhere in the call stack, the program will terminate by calling std::terminate(), which typically calls std::abort(). 
#include <iostream>
#include <stdexcept>

void dangerous_function() {
    throw std::runtime_error{"Oops!"};
}

int main() {
    dangerous_function();  // No try-catch!
    std::cout << "This will never print\n";
    return 0;
}
terminate called after throwing an instance of 'std::runtime_error' what(): Oops! Aborted (core dumped)

Best Practices

✓ Do

  • Use standard exception classes when possible
  • Catch exceptions by const reference
  • Order catch blocks from specific to general
  • Use meaningful error messages
  • Clean up resources before re-throwing
  • Document which exceptions a function might throw
  • Use exceptions for exceptional circumstances

✗ Don't

  • Use exceptions for normal control flow
  • Throw exceptions in destructors
  • Catch exceptions you can't handle
  • Ignore caught exceptions silently
  • Use catch (...) without re-throwing
  • Throw raw pointers or primitive types
  • Let exceptions escape from main()

Common Patterns

Pattern 1: Validate Input

void set_age(int age) {
    if (age < 0 || age > 150) {
        throw std::invalid_argument{"Age must be between 0 and 150"};
    }
    // ... rest of function
}

Pattern 2: Resource Cleanup

void process_file(const std::string &filename) {
    auto file = open_file(filename);
    try {
        // Process file (might throw)
        do_something_dangerous(file);
    }
    catch (...) {
        close_file(file);  // Clean up
        throw;             // Re-throw
    }
    close_file(file);
}

Pattern 3: Partial Error Recovery

int calculate_with_fallback(int x) {
    try {
        return risky_calculation(x);
    }
    catch (const std::exception &e) {
        std::cout << "Warning: " << e.what() << "\n";
        return 0;  // Fallback value
    }
}

Exception Guarantees

When writing functions that might throw exceptions, you should provide guarantees about program state:

  • No-throw guarantee: Function never throws (use noexcept)
  • Strong guarantee: If exception is thrown, program state is unchanged (atomic)
  • Basic guarantee: If exception is thrown, program state is valid but may be modified
  • No guarantee: Exceptions may leave program in invalid state (avoid this!)
// No-throw guarantee
int get_value() noexcept {
    return 42;
}

// Strong guarantee (atomic swap)
void swap(std::vector<int> &a, std::vector<int> &b) {
    std::vector<int> temp = a;  // Might throw, but a/b unchanged
    a = b;                        // Might throw, but a=temp, b unchanged
    b = temp;                     // Might throw, but a=b, b=temp
}

Quick Reference

Keyword Purpose
try { } Defines block where exceptions might occur
throw Throws an exception object
catch (type) Handles specific exception type
catch (...) Catches any exception (catch-all)
throw; Re-throws current exception
noexcept Specifies function won't throw

Summary

  • Exceptions provide a clean way to handle errors in C++
  • Use throw to signal an error, try to protect code, and catch to handle errors
  • Exceptions propagate up the call stack until caught
  • Always catch by const reference to avoid slicing and copying
  • Order catch blocks from most specific to most general
  • Use standard exceptions when possible, create custom ones for specific needs
  • Uncaught exceptions terminate the program
  • Clean up resources before re-throwing exceptions
  • Use exceptions for exceptional situations, not regular control flow
