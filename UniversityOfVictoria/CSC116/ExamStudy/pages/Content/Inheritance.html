Inheritance

Build related classes by reusing a base class, then extending it with derived classes.

Overview

Inheritance lets you define a base class (shared data + behaviors), then create a derived class that reuses the base and adds/changes features.

  • Base = “common stuff” (fields + functions)
  • Derived = “common stuff + extra”
  • Best for true is-a relationships (not just “can use”)
Exam reality: Most inheritance questions are about writing class definitions correctly (members, constructors, access), then using them in main().

Is-a vs Has-a

Use inheritance only when the derived type is-a more specific version of the base type.

  • Is-a (inheritance): Dog is-a Animal
  • Has-a (composition): Car has-a Engine
Rule of thumb: If you can’t say “X is a Y” out loud and it sounds right, don’t inherit.

Syntax

Basic inheritance is written with a : after the derived class name.

class Base {
public:
    void hello() { std::cout << "hi\n"; }
};

class Derived : public Base {
public:
    void extra() { std::cout << "extra\n"; }
};

int main() {
    Derived d;
    d.hello();  // from Base
    d.extra();  // from Derived
}
  • public inheritance is the most common for “is-a”.
  • You can inherit from multiple bases: class D : public A, public B (often avoided in intro courses).
Important C++ gotcha: class Derived : Base defaults to private inheritance. Be explicit: : public Base.

Public / Protected / Private

There are two separate ideas that people mix up:

  1. Member access (inside a class): public, protected, private
  2. Inheritance mode (between base and derived): public / protected / private inheritance

Member access (what derived classes can see)

  • public: anyone can access (via object)
  • protected: only the class and its derived classes can access
  • private: only the class itself can access
class Animal {
private:
    std::string secret;   // derived CANNOT access directly
protected:
    std::string name;     // derived CAN access
public:
    void setName(const std::string& n) { name = n; }
    std::string getName() const { return name; }
};

Inheritance mode (what the outside world sees)

  • public inheritance: base public stays public (best for “is-a”)
  • protected inheritance: base public becomes protected
  • private inheritance: base public becomes private (rare for this course)
Key memory hook: protected means “for me and my kids (derived classes)”, not for the outside world.

Constructors & Destructors

When you construct a derived object, the base part must be constructed first.

Calling a base constructor

class Item {
protected:
    std::string name;
public:
    Item(const std::string& n) : name(n) {}
    std::string getName() const { return name; }
};

class Food : public Item {
    int calories;
public:
    Food(const std::string& n, int c)
        : Item(n), calories(c) {}  // base ctor call

    int getCalories() const { return calories; }
};

Order rules (memorize these)

  • Construction: Base constructor runs first, then derived constructor body.
  • Destruction: Derived destructor runs first, then base destructor.
  • Initialization order: Members are initialized in the order they’re declared in the class, not the order in your initializer list.
Common bug: assigning fields inside the constructor body instead of using the initializer list. In C++ you should prefer : field(value) (especially for base constructors and const/reference members).

Overriding vs Hiding

Even without deep polymorphism, you’ll often need to understand what happens when a derived class uses the same function name as the base.

1) Overriding (polymorphism) needs virtual

If you want calls through a base pointer/reference to use the derived version, the base function must be virtual. (We’ll do a full dedicated page on this.)

2) Hiding (name hiding) happens even without virtual

class Base {
public:
    void print(int x) { std::cout << x << "\n"; }
};

class Derived : public Base {
public:
    void print(std::string s) { std::cout << s << "\n"; }
};

int main() {
    Derived d;
    d.print("hi"); 
    // d.print(5); // ERROR: Base::print(int) is hidden by Derived::print(string)
}
Fix (when needed): add using Base::print; inside Derived to un-hide base overloads.

Common Pitfalls

  • Private base data is not accessible in derived classes — use protected or provide getters/setters.
  • Forgetting : public Base (private inheritance default).
  • Object slicing: assigning a derived object to a base object copies only the base part.
    Rule: Use Base& / Base* when you want to preserve derived behavior.
  • Name hiding when you overload in the derived class (see above).
  • Wrong constructor calls: base constructor must be called in initializer list if it needs arguments.
  • Polymorphism without virtual destructor (advanced, but good to remember): if you ever delete through a base pointer, base destructor should be virtual.

Practice Prompts

Try these without looking anything up (closed-book practice).

  1. Write a base class Employee with protected members name and id, a constructor, and getters. Then write a derived class HourlyEmployee with hourlyRate, a constructor that calls the base constructor, and a function that returns weekly pay given hours.
  2. Write a base class Shape with a public function printType(). Derive Rectangle and add width/height. Make sure Rectangle can print both its type and its dimensions.
  3. Create a derived class that declares a function with the same name as a base function. Demonstrate (in comments) the “name hiding” problem and fix it using using Base::name;.
Self-check: For every class you write, confirm you have (1) correct access modifiers, (2) correct constructor signatures, (3) initializer lists, (4) correct base constructor call.

Fundamentals FAQ

Do derived classes automatically inherit constructors?

No (not in the simple way people assume). You typically define derived constructors and explicitly call a base constructor in the initializer list. (There are advanced features like inheriting constructors, but intro courses rarely rely on them.)

Can a derived class access base private members?

No. Use protected (if appropriate) or provide public/protected member functions (getters/setters) in the base.

What’s the difference between overriding and overloading?

Overloading = same name, different parameters (compile-time). Overriding = derived provides a new implementation of a virtual base function (run-time dispatch).

When will this matter on the exam?

When a question asks you to implement multiple related classes and then use them in a short main() test. Expect to write constructors, getters, and simple behaviors.
