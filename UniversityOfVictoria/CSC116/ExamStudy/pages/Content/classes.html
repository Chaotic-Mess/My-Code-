Classes & Objects

Master object-oriented programming fundamentals: creating classes, constructors, member functions, and encapsulation.

Related Topics: See String Constructors for real-world constructor examples.

Class Basics

A class is a user-defined type that bundles data (member variables) and functions (member functions) together.

Defining a Class

class Rectangle {
public:
    // Member variables (data)
    double width;
    double height;

    // Member function (behavior)
    double area() {
        return width * height;
    }
};
Don't forget the semicolon! Class definitions end with ;

Creating Objects

// Create an object (instance) of Rectangle
Rectangle rect;
rect.width = 5.0;
rect.height = 3.0;

std::cout << rect.area() << '\n';  // 15.0

// Create another independent object
Rectangle square;
square.width = 4.0;
square.height = 4.0;

std::cout << square.area() << '\n';  // 16.0

Struct vs Class

In C++, struct and class are nearly identical. The only difference is default access:

struct

  • Members are public by default
  • Often used for simple data containers
struct Point {
    int x;  // public by default
    int y;
};

class

  • Members are private by default
  • Preferred for encapsulation
class Point {
    int x;  // private by default
    int y;
};

Constructors

A constructor is a special member function that runs when an object is created. It initializes the object's data.

Default Constructor

Takes no parameters. If you don't write any constructor, the compiler generates a default one.

class Rectangle {
public:
    double width;
    double height;

    // Default constructor
    Rectangle() {
        width = 0.0;
        height = 0.0;
    }
};

Rectangle r;  // calls default constructor
std::cout << r.width << '\n';  // 0.0

Parameterized Constructor

Takes arguments to initialize member variables with specific values.

class Rectangle {
public:
    double width;
    double height;

    // Parameterized constructor
    Rectangle(double w, double h) {
        width = w;
        height = h;
    }
};

Rectangle rect(5.0, 3.0);  // width=5.0, height=3.0
Rectangle square{4.0, 4.0};  // uniform initialization
Important: Once you define any constructor, the compiler no longer generates a default constructor automatically. If you want both, you must define both.

Constructor Overloading

You can have multiple constructors with different parameter lists.

class Rectangle {
public:
    double width;
    double height;

    // Default constructor
    Rectangle() {
        width = 1.0;
        height = 1.0;
    }

    // Parameterized constructor
    Rectangle(double w, double h) {
        width = w;
        height = h;
    }

    // Square constructor (one parameter)
    Rectangle(double side) {
        width = side;
        height = side;
    }
};

Rectangle r1;           // calls default: 1x1
Rectangle r2(5.0, 3.0);  // calls parameterized: 5x3
Rectangle r3(4.0);      // calls square: 4x4

Member Initializer List

More efficient way to initialize members, especially for const members and references.

class Rectangle {
public:
    double width;
    double height;

    // Using initializer list (preferred)
    Rectangle(double w, double h) : width(w), height(h) {
        // Body can be empty or contain additional logic
    }

    // Default values in initializer list
    Rectangle() : width(1.0), height(1.0) {}
};
Best Practice: Use member initializer lists instead of assignment in the constructor body. It's more efficient and required for const/reference members.

Copy Constructor

Creates a new object as a copy of an existing one.

class Rectangle {
public:
    double width;
    double height;

    Rectangle(double w, double h) : width(w), height(h) {}

    // Copy constructor
    Rectangle(const Rectangle& other) {
        width = other.width;
        height = other.height;
    }
};

Rectangle original(5.0, 3.0);
Rectangle copy = original;  // calls copy constructor
Rectangle copy2{original};  // also calls copy constructor
Note: The compiler generates a default copy constructor that does member-wise copying. You only need to define your own if you have dynamic memory or special copying requirements.

Member Functions

Functions that belong to a class and operate on its data.

Defining Member Functions

class Rectangle {
public:
    double width;
    double height;

    Rectangle(double w, double h) : width(w), height(h) {}

    // Member function defined inside class
    double area() {
        return width * height;
    }

    // Declaration only (definition outside class)
    double perimeter();
};

// Definition outside class (note scope resolution ::)
double Rectangle::perimeter() {
    return 2 * (width + height);
}

Calling Member Functions

Rectangle rect(5.0, 3.0);

double a = rect.area();       // 15.0
double p = rect.perimeter();  // 16.0

The this Pointer

Inside a member function, this is a pointer to the current object.

class Rectangle {
public:
    double width;
    double height;

    // Using 'this' to avoid naming conflicts
    Rectangle(double width, double height) {
        this->width = width;   // member = parameter
        this->height = height;
    }

    // Returning *this for method chaining
    Rectangle& setWidth(double w) {
        width = w;
        return *this;
    }

    Rectangle& setHeight(double h) {
        height = h;
        return *this;
    }
};

Rectangle r(0, 0);
r.setWidth(5.0).setHeight(3.0);  // method chaining

Getters & Setters

Used to control access to private member variables.

class Rectangle {
private:
    double width;
    double height;

public:
    Rectangle(double w, double h) : width(w), height(h) {}

    // Getters (accessors)
    double getWidth() const { return width; }
    double getHeight() const { return height; }

    // Setters (mutators) with validation
    void setWidth(double w) {
        if (w > 0) width = w;
    }

    void setHeight(double h) {
        if (h > 0) height = h;
    }
};

Access Control

Access specifiers control which parts of your code can access class members.

Access Specifiers

public

  • Accessible from anywhere
  • Interface of the class

private

  • Only accessible within the class
  • Default for class
  • Enforces encapsulation

protected

  • Accessible in class and derived classes
  • Used in inheritance

Encapsulation Example

class BankAccount {
private:
    // Hidden implementation details
    double balance;
    std::string accountNumber;

public:
    // Public interface
    BankAccount(std::string accNum) 
        : balance(0.0), accountNumber(accNum) {}

    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    bool withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
            return true;
        }
        return false;
    }

    double getBalance() const {
        return balance;
    }
};

BankAccount account("12345");
account.deposit(100.0);
account.withdraw(30.0);

// account.balance = -1000; // ERROR: balance is private
std::cout << account.getBalance() << '\n';  // 70.0
Why Encapsulation?
  • Validation: Control how data is modified (e.g., prevent negative balances)
  • Flexibility: Change internal implementation without affecting users
  • Safety: Prevent accidental corruption of object state

Access Control in Practice

class Student {
private:
    std::string name;
    int studentID;
    double gpa;

    // Private helper function
    bool isValidGPA(double g) {
        return g >= 0.0 && g <= 4.0;
    }

public:
    Student(std::string n, int id) 
        : name(n), studentID(id), gpa(0.0) {}

    void setGPA(double g) {
        if (isValidGPA(g)) {
            gpa = g;
        }
    }

    double getGPA() const { return gpa; }
    std::string getName() const { return name; }
};

Const & Static Members

Const Member Functions

Promise not to modify the object. Required to call on const objects.

class Rectangle {
private:
    double width;
    double height;

public:
    Rectangle(double w, double h) : width(w), height(h) {}

    // Const member functions (don't modify object)
    double area() const {
        return width * height;
    }

    double getWidth() const { return width; }
    double getHeight() const { return height; }

    // Non-const member function (modifies object)
    void setWidth(double w) {
        width = w;
    }
};

const Rectangle rect(5.0, 3.0);
std::cout << rect.area() << '\n';     // OK: area() is const
// rect.setWidth(10.0);  // ERROR: can't call non-const on const object
Best Practice: Mark all member functions that don't modify the object as const. This allows them to be called on const objects and improves code safety.

Static Member Variables

Shared by all objects of the class. Only one copy exists.

class Student {
private:
    std::string name;
    static int studentCount;  // shared by all Students

public:
    Student(std::string n) : name(n) {
        ++studentCount;
    }

    ~Student() {  // destructor
        --studentCount;
    }

    static int getStudentCount() {
        return studentCount;
    }
};

// Must define static member outside class
int Student::studentCount = 0;

Student s1("Alice");
Student s2("Bob");

std::cout << Student::getStudentCount() << '\n';  // 2

Static Member Functions

Can be called without an object. Cannot access non-static members.

class Math {
public:
    static double square(double x) {
        return x * x;
    }

    static double cube(double x) {
        return x * x * x;
    }
};

// Call without creating an object
std::cout << Math::square(5.0) << '\n';  // 25.0
std::cout << Math::cube(3.0) << '\n';    // 27.0

Fundamentals FAQ

What's the difference between a struct and a class?

They're almost identical. The only difference is default access: struct members are public by default, while class members are private by default. In practice, use struct for simple data containers and class when you need encapsulation.

Why do I need a semicolon after a class definition?

Historical C++ syntax inherited from C. The semicolon allows you to declare variables of the class type immediately after the definition (though this is rarely done). Forgetting it is a common compile error.

What happens if I don't define a constructor?

The compiler generates a default constructor that does nothing (leaves members uninitialized). Once you define any constructor, the compiler stops generating the default one automatically.

When should I use an initializer list vs assignment in the constructor body?

Always prefer initializer lists. They're more efficient (direct initialization vs default-then-assign), and they're required for const members, reference members, and members without default constructors.

// Preferred
Rectangle(double w, double h) : width(w), height(h) {}

// Less efficient
Rectangle(double w, double h) {
    width = w;   // default initialization then assignment
    height = h;
}
What is this?

this is a pointer to the current object. It's useful when parameter names shadow member variables, or when you need to return the object itself (for method chaining).

Why make member variables private?

Encapsulation! Private members let you:

  • Validate data (e.g., ensure width > 0)
  • Change internal representation without breaking external code
  • Prevent accidental corruption of object state
What does const after a function mean?

It marks the function as a "const member function," promising not to modify the object's state. You can only call const member functions on const objects. Mark all functions that don't modify the object as const.

Can I call a member function inside a constructor?

Yes! The object is being constructed, but member functions can be called during construction:

Rectangle(double w, double h) : width(w), height(h) {
    if (area() < 0) {  // calling member function
        width = height = 1.0;
    }
}
What's the difference between a copy constructor and assignment operator?

Copy constructor creates a new object from an existing one (Rectangle r2 = r1;). Assignment operator copies to an already existing object (r2 = r1;).

When should I use static members?

Use static member variables when data should be shared across all instances (e.g., counting total objects). Use static member functions for utility functions that don't need object state (e.g., Math::square()).

Can a class have multiple constructors?

Yes! This is called constructor overloading. Each constructor must have a different parameter list (different number or types of parameters).

What happens when an object goes out of scope?

The destructor (if defined) is called automatically, and memory is freed. Destructors are named ~ClassName() and are used to clean up resources (close files, free memory, etc.).
